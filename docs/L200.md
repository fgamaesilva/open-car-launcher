# L200 Launcher

Android launcher for the Audio Tech Prime 9 QLED / NWD K2401P in the L200 Triton 2023. Work belongs exclusively to `fgamaesilva/open-car-launcher`, branch `feature/l200-monochrome`.

## Behavior

- Real local 24-hour clock and weekday/date use Android TextClock, including system time and timezone changes.
- Phone Link retains the existing ZLink/AutoKit/EasyConnection/Headunit Reloaded detection and manual picker. Navigation and Music retain persistent component selection. Hold any card to change its destination.
- Radio opens the selected native app. Without a saved destination, it searches installed radio/FM apps; otherwise it opens the searchable app picker. Hold Radio, or use launcher Settings, to change it.
- Applications opens the existing searchable drawer. BACK closes it without finishing HOME; HOME clears the drawer. Returning after 30 seconds also clears stale search.
- Header and bottom Settings open launcher settings. The default HOME selector is available there.
- App opening, app info, search and selected destinations work offline. No embedded player or hardware integration was added.

## Identity and dormant modules

Application ID: `com.fgama.l200launcher`. Kotlin namespace: `com.minimal.carlauncher`. Visible name: L200 Launcher. FileProvider uses `${applicationId}.fileprovider`. This installs alongside the original; preferences are separate Android app storage.

The old dashboard is retained in `view_legacy_dashboard.xml`. Its map/navigation/radio controllers use that separate generated binding. It is never inflated by L200 HOME. HOME does not create HomeViewModel, MapView or RadioWidgetController and never starts location, compass, tuner sessions or update checks. The radio repository is lazy. Updater checks and downloads are disabled, package-install permission is removed, and CI has no release publishing job. The previous dock controller and preferences remain in source but the configurable dock is no longer exposed. Dashcam automatic opening is dormant with the previous dashboard.

The fixed palette applies to both resource modes and the launcher icon. App icons in the existing drawer are supplied by installed apps. Insets include system bars, display cutouts and IME; the window uses adjustResize. Layout uses dp, weighted columns and sp, rather than treating 1280×720 physical pixels as dp.

## Build

Requirements: JDK 17, Gradle 8.9, Android SDK platform 35 and build-tools 34.0.0 (selected by AGP; 35.0.0 was also installed). The repository does not ship a complete Gradle wrapper. Local tools downloaded on this server are ignored in `.tools/`; `local.properties` is also ignored.

```sh
gradle --no-daemon :app:testDebugUnitTest :app:assembleDebug
```

Debug output: `app/build/outputs/apk/debug/app-debug.apk`. Debug signing is for testing; retain the same signing identity for subsequent installs that should preserve preferences.

## Physical head unit acceptance

Check actual density, font scaling, navigation/status bars and keyboard size; card labels and date must fit. Test ZLink and native radio selection, cold boot, app return, HOME/BACK, steering-wheel/physical keys, focus navigation, offline boot and persisted destinations after reboot. Vendor restrictions can prevent third-party apps from starting protected factory activities. No CAN Bus, MCU, root, brightness, firmware or telemetry code was added. Server compilation cannot validate these hardware behaviors.
